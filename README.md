# AI StudyMate — RAG-Powered ML/DL Study Assistant

A retrieval-augmented question-answering assistant for Machine Learning and Deep Learning topics. It only answers from a fixed set of 17 verified academic PDFs (arXiv papers, Stanford CS229 lecture notes, JMLR papers), runs entirely locally with Ollama, and refuses to answer anything it can't ground in a retrieved source. Core Track only — no computer vision, no image data.

## How it works

```
User question
     │
     ▼
Intent Router  ──▶ chitchat?  ──▶ canned reply, no retrieval
     │
     ▼ (in scope?)
Hybrid Retrieval
  dense search (Chroma + MiniLM embeddings)
  + BM25 keyword search
  + Reciprocal Rank Fusion
  + cosine-similarity rerank
     │
     ▼
Top 5 chunks, each given a deterministic ID (S1, S2, ...)
     │
     ▼
Ollama (llama3.2:3b) generates an answer citing only those IDs
     │
     ▼
Python checks the citations are real and match a retrieved chunk
  → invalid or missing citation = answer is thrown out, refusal returned instead
     │
     ▼
Answer + sources shown in the Streamlit UI
```

If the question is out of scope (not ML/DL), it's rejected before retrieval ever runs. If the retrieved sources don't actually support an answer, the system says so instead of guessing.

## Tech stack

- **Notebook / data pipeline:** PyMuPDF (PDF text + layout extraction), tiktoken (token counting for chunking), sentence-transformers (`all-MiniLM-L6-v2`), ChromaDB (persistent vector store), rank_bm25
- **LLM:** Ollama running `llama3.2:3b` locally (no cloud API)
- **Backend:** FastAPI, Pydantic, uvicorn
- **Frontend:** Streamlit
- **Tests:** pytest + FastAPI TestClient

## The corpus

17 PDFs, hand-picked and individually verified (real URL, real content, checked it actually extracts text before being trusted):

- arXiv papers: Attention Is All You Need, Adam, Batch Normalization, ResNet, LSTM: A Search Space Odyssey, GANs, VAEs, DDPM, k-NN tutorial
- JMLR papers: Dropout, Feature Selection (Guyon & Elisseeff)
- Stanford CS229 lecture notes: supervised learning, generative learning (Naive Bayes/GDA), SVM, unsupervised learning, bias-variance
- Random Forests (Breiman, official author copy)

One known gap: **backpropagation**. The obvious source (Rumelhart, Hinton & Williams 1986, *Nature*) only exists as a scanned PDF with no real text layer — pymupdf pulls out basically nothing from it, so it's useless for retrieval and was left out. The system correctly refuses to answer backprop questions instead of guessing from the LLM's own training data. This is documented, not a bug.

## Running it locally

### 1. Get the corpus
```
python scripts/download_papers.py
```
Downloads all 17 PDFs into `data/raw_pdfs/`, skips anything already there. Safe to re-run.

### 2. Build the pipeline
Open `notebooks/rag_pipeline.ipynb`, Restart Kernel → Run All. This chunks the PDFs, builds embeddings, and persists everything to `data/vector_store/`. Takes a few minutes, only needs to be done once (or whenever the corpus changes).

### 3. Backend
```
cd backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
uvicorn app.main:app --reload
```
Make sure Ollama is running with `llama3.2:3b` pulled (`ollama pull llama3.2:3b`).

Check it worked: open `http://localhost:8000/docs`.

### 4. Frontend
```
cd frontend
pip install -r requirements.txt
copy .env.example .env
streamlit run app.py
```

## Environment variables

**Backend** (`backend/.env`)

| Variable | Default | What it does |
|---|---|---|
| `VECTOR_STORE_PATH` | `../data/vector_store` | where the persisted Chroma DB lives |
| `OLLAMA_HOST` | `http://localhost:11434` | Ollama server address |
| `FRONTEND_ORIGIN` | `http://localhost:8501` | allowed CORS origin(s), comma-separated |
| `APP_ENV` | `development` | just affects logging |

**Frontend** (`frontend/.env`)

| Variable | Default | What it does |
|---|---|---|
| `API_BASE_URL` | `http://localhost:8000` | where the backend is running |

## API

**GET /health** — confirms the vector store loaded and returns the chunk count + model name.

**POST /query**
```
curl -X POST http://localhost:8000/query \
  -H "Content-Type: application/json" \
  -d '{"question": "What is overfitting?"}'
```
Response:
```json
{
  "answer": "Overfitting occurs when a model fits the training data too closely... (CS229 Bias-Variance Analysis, page 8, Section: Bias and Variance in practice)",
  "sources": ["CS229 Bias-Variance Analysis", "Dropout: A Simple Way to Prevent Neural Networks from Overfitting"],
  "sources_detail": [{"title": "...", "authors": "...", "page": "8", "section": "...", "source_url": "..."}],
  "intent": "in_scope",
  "citation_status": "valid",
  "is_refusal": false
}
```
Empty or missing `question` returns `422`.

## Evaluation

Ran 20 questions covering every required ML/DL topic, plus routing tests (chitchat, out-of-scope). Latest run:

- 19/20 grounded, correctly-cited answers
- 1/20 correct refusal (backpropagation — the documented corpus gap above)
- 6/6 routing tests correct (chitchat detection, out-of-scope rejection)

Full table in `data/processed/evaluation_results.csv` after running the notebook.

## Things worth knowing if you're reviewing this

- About 45% of chunks show `"Untitled Section"` as their section label. This isn't a bug — it means the source PDF had no detectable heading (no larger/bold font, no numbered heading) on that page, and the system was built to never invent a section name it can't verify.
- The LLM runs at `temperature=0` for reproducibility, and citations are validated in Python after generation — if the model cites something that wasn't actually retrieved, the answer gets thrown out and replaced with a refusal, rather than trusting the model to always cite correctly.
- No cloud APIs anywhere. Everything — embeddings, retrieval, generation — runs on your own machine.
